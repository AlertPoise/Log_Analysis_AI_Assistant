# UEBA 用户行为分析模块说明

## 1. 模块定位与分析目标

UEBA（User and Entity Behavior Analytics）模块用于基于历史登录/VPN 行为建立用户级行为基线，并对后续日志进行偏离度评估。

模块采用“历史行为建模 + 当前行为比对”的分析方式：首先为每个用户生成独立的行为基线，然后将待分析日志与该用户自身的历史模式进行多维度比对，最终输出可解释的异常评分结果。

核心输出包括：

- `ueba_score`：0 到 100 的异常评分，分值越高表示当前日志相对该用户历史行为的偏离程度越高。
- `ueba_risk_level`：由评分映射得到的风险等级，包括 `LOW`、`MEDIUM`、`HIGH`、`CRITICAL`。
- `ueba_anomaly_reasons`：评分贡献明细，记录触发的异常项、分值增量和相关证据。

因此，该模块不仅提供风险等级，还保留可审计、可复查的评分依据，便于解释单条日志被判定为异常的具体原因。

## 2. 业务处理链路

UEBA 的完整处理链路如下：

```text
结构化登录/VPN 日志
    ↓
选择历史时间窗口或受控训练样本
    ↓
按用户聚合历史行为特征
    ↓
生成用户行为基线
    ↓
选取待分析日志
    ↓
逐条比对用户行为基线
    ↓
输出异常评分、风险等级和评分原因
```

基线生成阶段用于回答：

```text
该用户的历史常态行为模式是什么？
```

日志评分阶段用于回答：

```text
当前日志相对该用户历史常态的偏离程度是多少？
```

## 3. 用户行为基线的含义

用户行为基线并非原始日志副本，也并非最近访问记录缓存，而是对用户历史行为进行聚合、筛选和摘要后形成的结构化行为画像。

当前基线主要包含三类信息：

- 常见行为集合：来源 IP、目标 IP、来源国家、来源城市、VPN 网关、活跃小时等高频特征。
- 行为分布特征：登录结果、事件类型、认证方式、客户端软件、协议等字段的历史占比分布。
- 统计摘要指标：失败率、非工作时间访问比例、异常 IP 比例、日均事件数、会话时长和流量均值等。

例如，若某用户在历史窗口内主要从固定城市、固定 VPN 网关、固定客户端并在工作时段登录，则这些模式会被固化为该用户的常态行为。当后续日志同时出现跨地域访问、新 VPN 网关、非工作时间访问和登录失败时，系统会基于多个偏离项累计得到更高的异常评分。

## 4. 行为基线生成机制

行为基线生成过程分为四个阶段。

第一，确定训练数据范围。系统按照时间窗口和 `log_type` 选取历史登录/VPN 数据。常规场景使用结构化日志表作为输入；在演示、验收或受控训练场景中，也可以先维护训练样本集合，再基于该集合重新生成基线。

第二，执行数据库侧聚合。系统优先在数据库中完成用户维度与行为维度的聚合统计，例如来源 IP 计数、来源城市计数、失败次数、活跃小时分布等，避免将大规模原始日志一次性加载到应用侧内存。

第三，合并用户级行为特征。系统将同一用户的多类聚合结果合并为统一的用户行为特征，包括常见网络来源、地域分布、认证方式、客户端分布、失败率和访问频率等。

第四，生成并保存基线记录。系统将用户行为特征转换为基线记录，保留 Top-N 常见项、比例分布和统计摘要，并形成可被后续评分流程查询的用户级基线。

当前默认基线参数如下：

| 参数 | 当前值 | 说明 |
|---|---:|---|
| 基线窗口 | 30 天 | 默认使用最近一段历史窗口生成用户行为基线 |
| 最小样本数 | 20 | 样本数达到 20 条时，基线被视为可靠 |
| 常见活跃小时阈值 | 5% | 某小时占比达到 5% 后进入常见活跃时段集合 |
| 常见来源 IP 阈值 | 3% | 某来源 IP 占比达到 3% 后进入常见来源 IP 集合 |
| 常见来源城市阈值 | 3% | 某城市占比达到 3% 后进入常见来源城市集合 |
| 常见 VPN 网关阈值 | 3% | 某 VPN 网关占比达到 3% 后进入常见网关集合 |
| 大多数 Top-N 维度 | 10 项 | 来源 IP、目标 IP、国家、城市、VPN 网关等维度默认保留前 10 项 |
| 活跃小时 Top-N | 24 项 | 小时维度最多覆盖 0 到 23 点 |

## 5. 基线指标说明

| 指标类别 | 基线字段 | 分析用途 |
|---|---|---|
| 样本与可靠性 | `sample_count`、`is_reliable` | 判断基线是否具备足够历史样本支撑 |
| 活跃时间 | `common_active_hours` | 描述用户常见活跃时段，并辅助解释非工作时间访问 |
| 来源网络 | `common_source_ips` | 判断当前来源 IP 是否偏离历史常见来源 |
| 访问目标 | `common_destination_ips` | 判断当前目标 IP 是否偏离历史访问目标 |
| 来源地域 | `common_source_countries`、`common_source_cities` | 判断是否出现历史少见或未出现过的来源地域 |
| VPN 接入入口 | `common_vpn_gateways` | 判断是否使用历史少见或未出现过的 VPN 网关 |
| 行为类型 | `action_distribution`、`event_type_distribution`、`result_distribution` | 描述历史事件类型、操作类型和登录结果分布 |
| 失败原因 | `fail_reason_distribution` | 描述失败登录中的原因分布 |
| 认证方式 | `auth_method_distribution` | 判断认证方式是否偏离历史分布 |
| 客户端与协议 | `client_software_distribution`、`protocol_distribution` | 判断客户端软件或协议是否偏离历史分布 |
| 失败率 | `failed_rate` | 衡量失败登录在该用户历史行为中的常见程度 |
| 非工作时间比例 | `off_hours_rate` | 衡量非工作时间访问在该用户历史行为中的常见程度 |
| 异常 IP 比例 | `unusual_ip_rate` | 记录历史日志中被标记为 unusual IP 的比例 |
| 访问频率 | `avg_daily_events`、`active_day_avg_events`、`max_daily_events` | 描述用户访问密度和峰值访问规模 |
| 会话与流量 | 会话时长均值/分位数、收发字节均值 | 描述用户常见会话持续时间和流量规模 |

这些指标共同构成用户历史行为模式的结构化表达，并作为后续异常评分的参照对象。

## 6. 基线可靠性规则

当前基线可靠性由样本数决定：

```text
sample_count >= 20 → 可靠基线
sample_count < 20  → 不可靠基线
```

不可靠基线不会被直接废弃，但评分结果会标记为 `UNRELIABLE_BASELINE`。在该状态下，除可靠性提示本身外，大部分偏离项会按 `0.5` 权重缩放，以降低样本不足导致的误判风险。

因此，系统仍会保留样本不足用户的行为偏离信号，但会在评分中降低其置信权重。

## 7. 日志异常评分机制

评分机制采用基于规则的可解释加分模型。系统首先查询待分析日志对应用户的基线，然后从地域、网络、接入入口、认证方式、客户端、协议、访问时间、登录结果和上游异常标记等维度进行比对。

当前主要检测维度包括：

- 来源国家是否属于用户常见国家集合。
- 来源城市是否属于用户常见城市集合。
- 来源 IP 是否属于用户常见来源 IP 集合。
- 目标 IP 是否属于用户常见目标 IP 集合。
- VPN 网关是否属于用户常见接入入口。
- 认证方式、客户端软件、协议是否出现在历史分布中。
- 当前日志是否发生在非工作时间。
- 当前日志是否为失败登录。
- 当前日志是否带有上游 unusual IP 标记。

每个命中的异常项会产生一个评分增量。系统将全部评分增量累加后限制在 0 到 100 之间，并进一步映射为风险等级。

## 8. 当前异常项权重

下表为当前实现中的实际评分规则。

| 异常项 | 触发条件 | 分值 | 说明 |
|---|---|---:|---|
| `NO_BASELINE` | 未找到用户基线 | 15 | 表示缺少历史参照基线，仅作为独立提示信号 |
| `UNRELIABLE_BASELINE` | 用户基线样本数不足 20 | 10 | 标记基线可靠性不足，并使后续多数偏离项按 0.5 权重缩放 |
| `NEW_SOURCE_COUNTRY` | 来源国家不在常见国家集合中 | 30 | 高权重地域偏离信号 |
| `NEW_SOURCE_CITY` | 来源城市不在常见城市集合中 | 15 | 城市级地域偏离信号；若国家同时为新国家，则降为 8 |
| `NEW_SOURCE_IP` | 来源 IP 不在常见来源 IP 集合中 | 12 | 来源网络偏离信号 |
| `NEW_SOURCE_IP`（长尾来源 IP 用户） | 用户来源 IP 分布高度分散，或未形成稳定来源 IP 集合但样本数已达 20 | 5 | 对来源 IP 高离散度用户降低惩罚权重 |
| `NEW_DESTINATION_IP` | 目标 IP 不在常见目标 IP 集合中 | 8 | 访问目标偏离信号 |
| `NEW_VPN_GATEWAY` | VPN 网关不在常见网关集合中 | 15 | 接入入口偏离信号 |
| `NEW_AUTH_METHOD` | 认证方式不在历史认证方式分布中 | 15 | 认证方式偏离信号 |
| `NEW_CLIENT_SOFTWARE` | 客户端软件不在历史客户端分布中 | 10 | 客户端环境偏离信号 |
| `NEW_PROTOCOL` | 协议不在历史协议分布中 | 10 | 协议使用偏离信号 |
| `OFF_HOURS` | 当前日志为非工作时间访问，且用户历史非工作时间比例低于 30% | 10 | 对低频非工作时间访问用户赋予较高权重 |
| `OFF_HOURS` | 当前日志为非工作时间访问，且用户历史非工作时间比例在 30% 到 60% 之间 | 5 | 对存在一定非工作时间访问习惯的用户降低权重 |
| `OFF_HOURS` | 当前日志为非工作时间访问，且用户历史非工作时间比例不低于 60% | 3 | 对高频非工作时间访问用户仅保留弱提示 |
| `LOGIN_FAILED` | 失败登录，且用户历史失败率不高于 2% | 20 | 对历史失败率极低用户的失败登录赋予较高权重 |
| `LOGIN_FAILED` | 失败登录，且用户历史失败率高于 2% 且低于 20% | 15 | 默认失败登录权重 |
| `LOGIN_FAILED` | 失败登录，且用户历史失败率不低于 20% | 8 | 对历史失败率较高用户降低单次失败登录权重 |
| `UNUSUAL_IP` | 当前日志带有 unusual IP 标记 | 20 | 来自结构化日志中的上游异常 IP 信号 |

补充规则如下：

- 当基线不可靠时，除 `UNRELIABLE_BASELINE` 本身外，大多数偏离项会乘以 `0.5`，四舍五入后最低保留 1 分。
- 最终评分会被限制在 0 到 100 之间。
- 多个异常项可以同时命中，最终风险由累计评分决定。

## 9. 风险等级映射

| 分数范围 | 风险等级 | 解释 |
|---:|---|---|
| 0-24 | `LOW` | 未出现明显偏离，或仅存在低权重提示信号 |
| 25-49 | `MEDIUM` | 存在明确偏离项，需要结合上下文进一步核查 |
| 50-74 | `HIGH` | 多个关键维度偏离，建议作为重点事件处理 |
| 75-100 | `CRITICAL` | 存在高强度或多维度叠加偏离，应优先复核 |

风险等级由 `ueba_score` 映射得到，不单独引入额外判定逻辑。

## 10. 评分结果解释

一条评分结果应重点关注以下字段：

| 字段 | 含义 | 分析方式 |
|---|---|---|
| `ueba_score` | 0 到 100 的异常评分 | 衡量当前日志相对用户历史基线的整体偏离程度 |
| `ueba_risk_level` | 风险等级 | 用于快速筛选和排序待复核日志 |
| `ueba_anomaly_reasons` | 评分原因列表 | 用于定位具体触发的异常维度和分值贡献 |
| `validation_status` | 评分状态 | `VALIDATED` 表示正常评分，`NO_BASELINE` 表示无可用基线，`UNRELIABLE_BASELINE` 表示基线样本不足 |
| `baseline_model_version` | 基线版本 | 用于确认评分所依据的基线版本 |

示例：

```text
ueba_score = 65
ueba_risk_level = HIGH
ueba_anomaly_reasons = NEW_SOURCE_COUNTRY + NEW_VPN_GATEWAY + LOGIN_FAILED
```

该结果表示当前日志同时触发来源国家偏离、VPN 网关偏离和失败登录信号，多个异常维度叠加后形成高风险评分。

## 11. 核心数据表的业务角色

| 表 | 业务角色 | 说明 |
|---|---|---|
| `logs_structured` | 结构化日志输入表 | 保存解析后的登录/VPN 行为日志，是基线生成和日志评分的主要数据来源 |
| `ueba_baseline_training_logs` | 受控训练样本表 | 用于管理可控训练样本，支持训练集替换、追加和版本化演示 |
| `user_behavior_baselines` | 用户行为基线表 | 保存用户在指定时间窗口和指定模型版本下的行为基线 |
| `ueba_validation_results` | UEBA 评分结果表 | 保存单条日志的评分、风险等级、异常原因、运行批次和源日志标识 |

上述表共同支撑从历史数据建模到新日志评分、结果追踪和审计复核的完整链路。
